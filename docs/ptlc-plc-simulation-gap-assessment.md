# PTLC PLC 仿真能力评估与后续建设建议

更新日期：2026-08-20
适用分支：`PTLC`

## 结论

当前 PLC-SIM 已达到 **Uni-Lab OS 联调级 PLC 仿真后端** 的目标：能够替代 PTLC_UI
中的 PLC 仿真职责，为 OS Backend 提供稳定的 OPC UA 节点、L2 握手、动作时序、执行器反馈、
现场输入与故障注入能力。它已经适合工作流联调、协议回归和大部分设备动作测试。

当前实现尚不能等同于真实 PLC，也不是高保真数字孪生。若目标是覆盖急停、断电恢复、
通信故障、执行器卡滞、液体连续过程和运动学边界等验收场景，仍需补齐下文列出的能力。

正式系统边界保持不变：**Uni-Lab OS FE + OS Backend + PLC-SIM** 共同替代 PTLC_UI；
OS Backend 负责工作流、资源锁和跨设备协调，PLC-SIM 只负责 PLC 可观察、可控制的现场行为。

## 仍需补齐的能力

### P0：影响 PLC 故障场景与恢复可信度

1. **全局 PLC 状态机**

   需要让 `PLCStart`、`PLCStop`、启动/回零、急停、轴通信、轴故障和报警复位真正参与
   动作门禁。目前部分全局量仍偏静态，无法完整验证停机、恢复和全局联锁。

2. **故障和互锁的物理过程**

   当前气缸和轴在未注入动作级故障时会按计划成功，传感器也没有抖动、卡滞、断线等模型。
   Develop A26 等少数动作还需补充连续空状态复位和瓶盖超时错误等细粒度过程故障。

3. **复位、重启和并发一致性**

   延迟传感器转换需要与所属动作绑定，并在中断、复位时可靠取消；进程重启还不能恢复正在
   运行的物理周期；多个通道共享同一执行器时，需要统一仲裁，避免不可能的并发状态。

4. **协议漂移强制保护**

   `PTLC_REFERENCE_ROOT` 目前是可选校验。CI 应固定拉取或缓存权威 PTLC domain 版本，强制
   对比节点、动作、错误码和行为规格，避免参考仓库更新后 PLC-SIM 静默落后。

### P1：影响过程和运动仿真精度

5. **泵、阀和液体连续过程**

   当前以动作时序和终态为主。后续应完整执行 DT token、阀切换、速度、忙状态和体积累计，
   并维护罐体体积/液位的连续变化，而不是只在动作结束时更新结果。

6. **CNC 与运动模型**

   当前轴为固定时长或线性匀速模型。需要时再增加加减速、软限位、跟随误差、回零过程、
   超程和碰撞门禁。该项应服务 PLC 联锁测试，不扩展为机器人运动学模拟器。

7. **输入与诊断可解释性**

   需要补齐 IX12 工具检测等外部事实的正式输入契约，并在 GUI/API 中展示门禁失败原因、
   阻塞传感器、等待条件和预计反馈时间，降低“等待执行”问题的排查成本。

### P2：影响与真实控制器的一致性

8. **OPC UA 运行时保真度**

   当前重点是节点值与业务协议，不模拟 CODESYS/Inovance 的订阅负载、会话中断、网络抖动、
   写入质量码和重连细节。只有在需要做 Edge 通信韧性验收时，才建议建设这一层。

## 明确不属于 PLC-SIM 的职责

以下能力由 OS Backend 或其他设备模拟模块负责，不应重新并入 PLC-SIM：

- 工作流 DAG 调度、跨设备资源锁、业务重试和任务恢复；
- 机器人轨迹、夹爪运动学、碰撞和机器人控制器协议；
- 相机成像、视觉算法与检测结果生成；
- 业务物料台账、库存和实验数据管理。

这些模块只需通过联合仿真事件，把 PLC 能观察到的现场事实输入 PLC-SIM，例如物料到位、
工具检测或站点占用状态。

## 推荐建设顺序

面向“输入 PLC 工程或设备变量表，由 AI 辅助生成仿真器与设备握手”的通用化建设，已拆分为
[AI PLC 仿真器工厂实施计划](../plan/feature-ai-plc-simulator-factory-v1.md)。该计划把本评估中的
能力缺口转换为证据抽取、AI 结构化补全、确定性编译、生成包运行与工站预调试验收任务。

1. 建立全局 PLC 运行状态、急停、轴故障、报警复位、Rail Sync 和 FreeMove 门禁。
2. 将动作时序统一到可取消、可恢复的扫描周期内核，补齐复位/重启与共享执行器仲裁。
3. 在 CI 中强制执行 PTLC domain 漂移检查，并用真实 PLC 或 PTLC 参考仿真的事件轨迹做差分测试。
4. 按实际验收需求逐步深化液体连续过程、运动模型和 OPC UA 故障保真度。

## 架构建议

继续深化现有 `PtlcPlant + PtlcSensorEngine` 边界：前者承载 PLC 动作、执行器与过程规则，
后者承载外部事实、延迟反馈和输入字节合成；`PtlcHandshakeAgent` 只协调 L2 请求和生命周期。
不要回到“每个工作流一个握手代理”的模式。设备包级常驻仿真可以复用同一套 PLC 状态，
也更适合处理并发、复位、重启和跨工作流连续现场状态。

## 验证说明

本结论基于 `PTLC` 分支代码、内置行为快照和自动化测试得出，尚未以真实 PLC 硬件做逐周期
对照验证。因此“联调级”表示协议与业务行为可验证，不代表已经达到硬件在环或认证级仿真精度。
