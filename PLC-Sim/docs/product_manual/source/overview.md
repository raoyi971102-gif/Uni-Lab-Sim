# 认识 PLC-Sim

PLC-Sim 是面向 PLC / OPC UA 联调的仿真应用。它在没有真实产线、设备不可占用或联调成本较高时，按点表提供可独立安装的 OPC UA 端点，用来验证连接、点位映射、握手顺序、超时和故障处理。

它不负责让实验室完成一次实验，而是回答以下问题：

- 主站或 Uni-Lab OS 驱动能否连上约定的协议地址；
- 点位名称、数据类型、读写方向和初值是否与点表一致；
- 命令、接受、执行、完成、复位和故障是否按约定顺序变化；
- 超时、拒绝、断线和未知结果会不会被误判为成功；
- 同一套点表和配置能否重复用于本机联调和自动化测试。

## 它在联调链路中的位置

一次典型的 PLC 联调按这个顺序发生：

1. **准备点表**：从 PLC 工程或供应商点表得到变量名、类型、NodeId 和业务含义。
2. **启动协议端点**：PLC-Sim 按点表创建 OPC UA 节点。
3. **启动握手代理**（设备包声明需要时）：按公开协议读写节点，模拟工站状态变化。
4. **连接主站**：Uni-Lab OS 或其它客户端按启动图中的 Endpoint 建立会话。
5. **只读检查与安全测试**：先读状态，再写无硬件副作用的测试命令，最后才做完整动作。
6. **记录结果**：保存仿真器版本、点表、Endpoint、动作名称、结果和清理状态。

> 点表与配置 → 协议服务就绪 → 可选握手代理 → 主站建立会话 → 只读核对 → 受控写入 → 复位与故障路径

Uni-Lab OS 负责工作流、物料、库存、库位和跨设备调度。PLC-Sim 只提供协议层和 PLC 能看到的现场事实。两边不能互相代替。

## 五项核心能力

### 协议端点

PLC-Sim 读取一份或多份 CSV（或 PTLC 节点快照）并创建 OPC UA 节点，默认 Endpoint 为 `opc.tcp://127.0.0.1:4855/xuse_sim/`。

端点“在监听”只代表进程和端口可用，不代表点表正确，也不代表主站已经连上正确的命名空间。

### 变量表与工程导出

可以把 InoProShop 工程中的 GVL 导出为 CSV，也可以直接导入已有点表。CSV 至少包含名称、英文名、节点类型、数据类型、语言和 NodeId。NodeId 是工程或供应商导出的接口事实，不能按中文名或数组下标猜测。

工程打开、保存和编译依赖 Windows、InoProShop 和 MCP bundle，属于 <span class="status status-config">需要配置</span>。只使用现成 CSV 时不需要这些依赖。

### 握手代理

握手代理通过公开 OPC UA 或 HTTP 接口观察节点并产生可追踪结果。当前内置三类代理：

- SZLab：设备包级常驻，覆盖 Robot、S04–S09 和 S1 HTTP；
- PTLC V2：八个 L2 通道和 55 个已建模 PLC 动作；
- XUSE：全局握手入口。

代理不得写入 PLC 拥有的完成位、传感器、安全信号或故障位来制造通过。固定延时不能代替可观察握手。

### 页面观察与受控测试

Web GUI 用于打开工程、导入点表、启停服务、监视变量和查看连接。页面只用于观察和受控测试。共享环境中不要修改点位、切换场景或停止别人正在使用的服务。

GUI 维护写入和握手代理不能同时成为同一节点的写入方。

### 故障与恢复观察

可以模拟拒绝、超时、挂起和断线，确认主站明确失败且不会自动重复危险动作。仿真器重启后，主站应按设备包规定的策略恢复连接。这些路径必须单独验证，不能只跑成功用例。

## 先理解六个核心对象

| 对象 | 业务含义 | 典型内容 |
| --- | --- | --- |
| 点表 / CSV | 协议节点的权威清单 | 名称、类型、读写方向、NodeId、初值 |
| Endpoint | 主站应连接的协议地址 | `opc.tcp://host:port/path/`，不是 HTTP 管理页 |
| 命名空间 | OPC UA 节点所属空间 | Namespace URI 优先；Index 重启后可能变化 |
| 握手代理 | 按协议读写节点的适配进程 | 命令、Busy、完成、复位、超时 |
| 启动图节点 | Uni-Lab OS 里对应的设备实例 | 设备类、Endpoint、超时、点位对照 |
| 就绪检查 | 判断能否开始联调 | 进程、协议服务、主站会话三层都通过 |

这些对象之间的关系可以概括为：

> 点表定义节点；Server 暴露 Endpoint；握手代理按协议改变节点；Uni-Lab OS 通过启动图连接 Endpoint；就绪检查分别确认进程、协议和主站。

## 使用边界

为避免把“仿真结果正确”误解为“现场一定安全”，使用时必须遵守以下原则：

- 仿真器只证明软件合同和协议链路基本一致，不能代替急停、互锁、限位和人员防护验收；
- Uni-Lab OS 的调度器、工作流、物料、库存和库位权威不在 PLC-Sim；
- 默认配置面向本机和可信实验室网络，不包含公网鉴权；
- 在线下载 PLC 程序当前关闭，不能用 GUI 代替供应商部署流程。
