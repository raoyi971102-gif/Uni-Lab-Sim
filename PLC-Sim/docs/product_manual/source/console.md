# 仿真器页面上手

本页介绍 PLC-Sim 网页的日常入口、页面状态和基本操作。产品能力见[认识 PLC-Sim](overview.md)；从零部署请先阅读[系统安装](installation.md)。

:::{admonition} 阅读角色
- **业务负责人**：确认本次联调目的、点表来源和允许写入的范围。
- **开发人员**：启动页面、导入点表、观察节点和连接主站。
- **验收人员**：核对 Endpoint、命名空间、节点数量和停止顺序均可追溯。
:::

## 打开与识别当前界面

默认地址是 `http://127.0.0.1:18765/`。启动命令为 `plc-sim` 或 `plc-sim gui`。

本手册的日常操作以本机 Web 页面为准。安装包会自动打开浏览器；源码启动也可以加 `--no-open`，只监听不弹窗。

:::{warning}
页面能打开只证明 GUI 进程在运行。OPC UA Server 和握手代理是独立服务，必须在对应页面或日志里单独确认。
:::

## 页面分区

| 区域 | 主要用途 | 写操作 |
| --- | --- | --- |
| **工程** | 打开 `.project`，查看 POU/GVL，保存或编译。 | 有，且依赖 InoProShop |
| **提取变量** | 选择 GVL，预览并导出 CSV。 | 写出 CSV 文件 |
| **OPC UA 仿真** | 选择点表、启动或停止 Server 与握手代理。 | 有 |
| **在线变量** | 搜索节点、加入监控栏、定时读取或维护写入。 | 默认只读；维护写入需显式勾选 |
| **客户端连接** | 查看 TCP 连接数、Session 和来源地址。 | 无 |
| **诊断** | 查看进程日志和近期错误。 | 无 |

工程相关能力在 Windows 上且已安装 InoProShop、Node.js 和 MCP bundle 时为 <span class="status status-config">需要配置</span>。其它平台打开工程为 <span class="status status-unavailable">当前不可用</span>，应直接使用已有 CSV。

## 如何判断当前能不能操作

先看仿真服务页，而不是只看浏览器标题。

| 现象 | 含义 | 应对 |
| --- | --- | --- |
| GUI 已打开，Server 未启动 | 只能导入点表，不能被主站连接 | 先启动 Server |
| Server 已启动，代理未启动 | 节点存在，但不会按工站协议自动变化 | 只读检查可以开始；需要握手时再启动代理 |
| 代理已启动，主站未连接 | 仿真器侧就绪，OS 或其它客户端尚未建会话 | 检查启动图里的 Endpoint |
| 在线变量能读到值 | 当前 Session 可读该节点 | 再核对类型、命名空间和业务含义 |
| 客户端连接数为 0 | 还没有 OPC UA 客户端连上 | 不要把 GUI 自身误当成主站已连接 |

断线或停止 Server 后，监控栏里的旧值不能当作当前现场事实。

## 第一次建议只做这些事

1. 打开 PLC-Sim 页面，进入“OPC UA 仿真”。
2. 确认 profile 为 `csv`，点表指向 `data/demo_variables.csv` 或 `data/szlab_plc_0810.csv`。
3. Host 填写 `127.0.0.1`，Port 填写 `4855`。
4. 启动 Server，在日志中看到节点数量和 Endpoint。
5. 在“在线变量”里搜索一个只读状态点，核对名称、类型和初值。
6. 不要勾选维护写入，不要启动第二个代理，不要改生产点表。

需要 SZLab 或 PTLC 握手时，再按[握手代理](handshake.md)启动对应代理。需要接到 Uni-Lab OS 时，再按[与 Uni-Lab OS 联调](os-integration.md)填写启动图。

## 写入前先确认写入方

同一节点同一时间只能有一个写入方：

- 握手代理运行时，GUI 默认禁止把 PLC 输出点写成“完成”或“故障”；
- 只有显式勾选“维护写入”才能临时覆盖，用完后立刻关闭；
- 不要同时开两个握手代理，也不要让外部控制器和代理抢写同一命令点。

## 刷新与停止

执行启动、停止或写入后，以页面重新拉取的服务端结果和进程日志为准。关闭时先停握手代理，确认动作回到安全初始态，再停 Server，最后关 GUI。不要直接关掉 Server 窗口让代理无限重连。
