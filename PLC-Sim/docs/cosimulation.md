# 联合仿真步确认接口

`plc_sim.cosimulation.CoupledSession` 管理一个隔离仿真世界；设备包注入控制器、命令通道和采样通道，后端实现 `PhysicsPort`。不解析部署图，也不自动连接任何真机。

创建会话 → `register_controller(..., reset=...)` → `reset()` → 暂停态单步或 `resume()` 连续推进。控制器读取上一确认步的输入，输出经唯一写者检查后交给物理后端；只有完整确认身份、时间和采样集合后才提交当前 tick。每次复位尝试使用新 epoch，即使确认丢失也不复用。异常置为 faulted 并保留 pending；上层只能审计或显式复位，不能盲目重发。

`Channel` 使用整数物理步定义采样周期、交付延迟和 TTL。`Sample` 的 acquired_tick 和 sequence 必须来自实际采集，重复数据不能刷新 TTL，无效或过期读取返回 None。控制器必须将 None 当作未知，不能当作到位。扫描周期可以不同；倍率只改变墙钟等待，不改变物理步长、扫描或传感器的逻辑时间。

生命周期与 SDK 调用在创建会话的线程执行。ROS/HTTP 工作线程应将请求交给世界线程，不得自行调用 step。世界 reset 不等同于电气握手 Reset、取消动作或恢复接管；暂停也不是实际运动停稳证明。

该模块提供进程内机制，不提供跨进程 RPC、持久恢复、Twin 真机权限隔离或具体设备到位判据。这些能力不能从单元测试通过推导完成。`tests/test_cosimulation.py` 覆盖确认丢失、错世界/epoch、采样倒退、写者冲突、延迟/过期、线程与重入边界；真实物理资格由 Testbed 单独验收。
