# PLC-Sim 使用说明

版本：以当前分支源码和安装包版本为准
适用对象：需要从 InoProShop 工程导出 OPC UA 变量、启动 PLC-Sim Server，或调试 SZLab
握手代理的使用者和 AI。

本文只说明 **PLC-Sim**，不说明自动化验收包的用例清单、证据等级或验收报告。PLC-Sim
本身负责变量表驱动的 OPC UA 仿真、SZLab 握手代理、Web GUI 和工程/MCP 命令行；它不拥有
Uni-Lab-OS 的调度器（Scheduler）、工作流（Workflow）、物料（Material）、库存（Inventory）
或库位（Site）权威。

## 1. PLC-Sim 是什么

PLC-Sim 由四个可独立运行的部分组成：

| 部分 | 作用 | 入口 |
|---|---|---|
| OPC UA Server | 读取一个或多个 CSV 变量表并创建 OPC UA 节点 | `plc-sim server`、`server.py` |
| SZLab 握手代理 | 通过 OPC UA/HTTP 模拟 SZLab 设备包的公开握手和状态变化 | `plc-sim szlab-handshake`、`szlab_handshake_agent.py` |
| Web GUI | 工程打开、GVL 提取、CSV 导入、Server/代理启停、在线诊断 | `plc-sim gui`、`start_gui.bat` |
| InoProShop MCP CLI | 通过公开 MCP 接口读取工程结构、提取 GVL、保存和编译 | `python -m ino_mcp.cli` |

Server 和握手代理是两个进程：Server 创建节点，握手代理按节点名称读写节点。握手代理
不读取 CSV；因此 Server 必须加载与 PLC 工程或供应商点表一致的 CSV。

## 2. 安装和启动

### 2.1 使用者：安装包启动

PLC-Sim 和 Modbus-Sim 保持多平台交付策略。Windows 用户可以直接安装
`PLC-Sim-Setup-Windows-x64-*.exe`，从开始菜单启动 PLC-Sim，不需要 Python、pip 或 Git。
首次启动若出现 SmartScreen，请先用同一 Release 的 `SHA256SUMS.txt` 校验安装包；当前
安装包没有商业代码签名。

Windows 安装包内的 GUI、OPC UA Server 和 SZLab 握手代理可以直接使用。只有“打开
InoProShop 工程、读取 POU/GVL、编译”依赖 InoProShop、Node.js 和 MCP bundle。

### 2.2 AI/开发者：源码启动

PLC-Sim 要求 Python 3.11.x。Windows：

```powershell
cd C:\path\to\PLC-Sim
setup_venv.bat
.\.venv\Scripts\python.exe -m pip install -e .
start_gui.bat
```

`setup_venv.bat` 足以运行仓库内的 `.bat`/`.py` 入口；额外的 `pip install -e .` 用于安装
`plc-sim` 和 `python -m plc_sim` 统一入口。

跨平台开发也可以直接安装：

```bash
python3.11 -m venv .venv
./.venv/bin/python -m pip install -e .
./.venv/bin/python -m plc_sim --help
```

若已安装 wheel，可使用统一入口：

```text
plc-sim                 # 启动 Web GUI
plc-sim gui --help
plc-sim server --help
plc-sim szlab-handshake --help
```

核心 Server、握手代理和 Web GUI 保持多平台；InoProShop 工程编辑和 GVL 提取属于 Windows
专用能力，因为 InoProShop 本体只在 Windows 上可用。

## 3. 完整 GUI 流程

### 3.1 使用者：打开工程

1. 双击 `start_gui.bat`，浏览器打开 `http://127.0.0.1:18765/`。
2. 在工程区域填写绝对路径的 `.project` 文件，点击“打开工程”。
3. 等待工程结构和 GVL 列表加载；需要确认代码可编译时再点击“保存”或“编译”。
4. “下载程序块”不是变量导出步骤。在线下载属于非幂等设备操作，PLC-Sim GUI 当前
   默认拒绝在线下载，不要用它代替供应商部署流程。

如果只已有 CSV，不需要打开工程，可直接进入“OPC UA 仿真”页。工程编辑需要：

- Windows；
- InoProShop V1.9.1.6（SP11 内核）；
- Node.js 18 或更高版本；
- `PLC-Sim/vendor/inoproshop-mcp/bundle.min.js` 或授权的同版本 MCP bundle。

### 3.2 使用者：导出变量表

1. 切换到“提取变量”页，点击“刷新列表”。
2. 选择包含 PLC 通讯变量的 GVL；找不到时先查看工程结构，或填写手工 GVL 路径。
3. 点击“预览数据”，确认以下字段：

   `Name`、`EnglishName`、`NodeType`、`DataType`、`NodeLanguage`、`NodeId`。

4. 设置 Namespace index、NodeId 前缀和输出路径。`ns=4` 只是 SZLab 示例，实际值必须
   以工程的 Namespace Array 和导出的 NodeId 为准。
5. 需要完整点表时选择“全部变量/未标记变量”和“展开结构体”；只需要公开 symbol 时，
   保持默认的标记变量范围。
6. 点击“提取并保存”，将 CSV 保存到受控目录，导出后不要在同一文件上并行修改。

CSV 的最小格式如下：

```csv
Name,EnglishName,NodeType,DataType,NodeLanguage,NodeId
工站初始化,Station_Initialize,VARIABLE,BOOLEAN,Chinese,ns=4;s=uniab|工站初始化
```

支持的数据类型为 `BOOLEAN`、`INT16`、`INT32`、`FLOAT` 和 `STRING`。NodeId 是 PLC/OPC UA
导出的接口事实，不能根据中文名、英文名或数组下标猜测、拼接或批量替换。

### 3.3 使用者：导入变量表并运行 OPC UA Server

这里的“导入”是把 CSV 交给 Server 建立仿真节点，不是把 CSV 写回 PLC 工程：

1. 切换到“OPC UA 仿真”或“仿真服务”页，选择 `csv` profile。
2. 在 CSV 路径框填写文件，或通过文件选择器上传。支持多份 CSV；重复节点按界面提示
   处理，启动前应确认合并后的 NodeId 唯一。
3. 设置 Host、Port、Namespace URI 和 Namespace index。
4. 单机调试使用 Host `127.0.0.1`；只有在防火墙和网络隔离已确认时才监听 `0.0.0.0`。
5. 点击“启动服务”，检查日志中的 CSV 路径、节点数量和 Endpoint。

默认 Endpoint：

```text
opc.tcp://127.0.0.1:4855/xuse_sim/
```

Server 运行期间不要替换 CSV。换表时按“停止握手代理 → 停止 Server → 更换 CSV → 重启
Server → 重启握手代理”的顺序执行。

### 3.4 使用者：启动 SZLab 握手代理

1. 在“握手代理”区域选择 `SZLab` profile。
2. 填写与 Server 一致的 Host、Port、Endpoint 和 `config/szlab_handshake.yaml`。
3. 默认选择“设备包就绪场景”。该模式一次启用 Robot、S04 六工位、S05、S06、S07、
   S08、S09、PLC 和 S1 HTTP 协议族，而不是只模拟某一条业务流程。
4. 需要诊断单一协议时才指定单个工作流；这不改变设备包模式的通用分派设计。
5. 点击“启动代理”，确认日志显示 OPC UA 已连接、节点先决条件可读，并在状态页看到
   `state-file` 快照更新。

S1 的本地 HTTP stand-in 通常使用 `127.0.0.1:8055`。如果已有外部 S1 服务，应明确配置
地址并避免同时启动两个监听者。

### 3.5 使用者：停止服务

关闭时先停止握手代理，再确认动作已回到安全初始态，最后停止 OPC UA Server。不要直接
关闭 Server 窗口让代理无限重连，也不要让 GUI 维护写入和握手代理同时写同一变量。

## 4. AI/CLI 等价流程

以下命令默认在 `PLC-Sim` 目录执行。PowerShell 使用反引号续行；CI 中也可以写成单行。

### 4.1 AI：检查工程结构

```powershell
cd C:\path\to\PLC-Sim
.\.venv\Scripts\python.exe -m ino_mcp.cli structure `
  --project "C:\project\XUSE.project" `
  -o "C:\project\evidence\project-structure.json"
```

需要保持 InoProShop 会话时：

```powershell
.\.venv\Scripts\python.exe -m ino_mcp.cli open `
  --project "C:\project\XUSE.project" --keep-alive
```

MCP 配置只通过 CLI 参数或公开环境变量覆盖：

```powershell
$env:PLCSIM_MCP_BUNDLE = "C:\path\to\PLC-Sim\vendor\inoproshop-mcp\bundle.min.js"
$env:PLCSIM_INOPROSHOP_EXE = "C:\Program Files\InoProShop\InoProShop.exe"
$env:PLCSIM_NODE = "node"
```

不要扫描或导入 Uni-Lab-SZLab、Uni-Lab-OS 等兄弟仓库源码，也不要修改 `sys.path` 来绕过
MCP 接口。

### 4.2 AI：导出 GVL 变量表

```powershell
$project = "C:\project\XUSE.project"
$csv = "C:\project\evidence\szlab_variables.csv"
$nodePrefix = "uniab|" # 示例；必须替换为工程导出的真实 NodeId 前缀

.\.venv\Scripts\python.exe -m ino_mcp.cli extract `
  --project $project `
  --out $csv `
  --gvl "Application/GVL_XUSE" `
  --all `
  --name-mode comment `
  --ns-index 4 `
  --ns-prefix $nodePrefix
```

参数说明：

- `--gvl` 可重复；不确定路径时先运行 `structure`；
- `--all` 导出全部变量，不带该参数时只导出带 symbol attribute 的变量；
- `--name-mode comment` 使用中文注释，必须确认注释稳定；
- `--ns-index` 和 `--ns-prefix` 必须来自工程/点表事实，不能为了让代理连接成功而猜测。

可用 `pipeline` 一次完成“提取 + 启动 Server”：

```powershell
.\.venv\Scripts\python.exe -m ino_mcp.cli pipeline `
  --project $project --out $csv --gvl "Application/GVL_XUSE" --all `
  --name-mode comment --ns-index 4 --ns-prefix $nodePrefix `
  --serve --host 127.0.0.1 --port 4855
```

`pipeline` 不会启动 SZLab 握手代理；代理仍需要单独启动。

### 4.3 AI：启动 OPC UA Server

CLI 没有额外的“导入 CSV”子命令，`server --csv` 就是导入动作：

```powershell
.\.venv\Scripts\python.exe -m plc_sim server `
  --host 127.0.0.1 `
  --port 4855 `
  --csv $csv `
  --ns-uri "urn:xuse:sim" `
  --ns-index 4
```

多份表可以重复 `--csv`：

```powershell
.\.venv\Scripts\python.exe -m plc_sim server `
  --csv "C:\project\base.csv" `
  --csv "C:\project\szlab-extra.csv" `
  --host 127.0.0.1 --port 4855
```

也可以使用 Windows 启动器：

```bat
start.bat "C:\project\szlab_variables.csv"
```

保持 Server 终端运行；另开终端执行握手代理。

### 4.4 AI：列出、检查和启动握手代理

`list` 只输出代理支持的工作流和先决条件，不连接 OPC UA：

```powershell
.\.venv\Scripts\python.exe szlab_handshake_agent.py list `
  --config config\szlab_handshake.yaml
```

`check` 建立 OPC UA 会话并执行只读先决条件检查，不进入持续动作循环：

```powershell
.\.venv\Scripts\python.exe szlab_handshake_agent.py check `
  --url "opc.tcp://127.0.0.1:4855/xuse_sim/" `
  --config config\szlab_handshake.yaml `
  --workflow all
```

`serve` 启动设备包模式：

```powershell
.\.venv\Scripts\python.exe szlab_handshake_agent.py serve `
  --url "opc.tcp://127.0.0.1:4855/xuse_sim/" `
  --config config\szlab_handshake.yaml `
  --package-config config\szlab_package.yaml `
  --state-file data\runtime\szlab-package-state.json `
  --s1-host 127.0.0.1 --s1-port 8055 `
  --time-scale 10
```

统一入口等价于：

```powershell
.\.venv\Scripts\python.exe -m plc_sim szlab-handshake `
  --url "opc.tcp://127.0.0.1:4855/xuse_sim/" --time-scale 10
```

也可以用 `start_all.bat` 同时启动 Server 和代理，或用 `start_szlab_handshake.bat` 只启动
代理。批处理脚本适合人工快速启动；AI/CI 应优先使用显式 CLI，以便记录参数和退出码。

## 5. SZLab 握手代理建设规范（PLC-Sim 范围）

### 5.1 给使用者看的规范

握手代理是一个通过公开 OPC UA/HTTP 接口运行的协议适配器，不是某一条固定业务流程的
脚本。它应根据设备能力和协议配置，接收动作参数，观察 PLC 状态并产生可追踪结果。

一个动作至少要有：

1. 可观察的就绪/允许状态；
2. 明确的请求或参数提交边沿；
3. 独立的接受/Busy 状态（如果 PLC 协议提供）；
4. 独立的完成、错误或超时结果；
5. 可重复执行的复位和安全清理。

推荐状态机：

```text
IDLE/READY → ACCEPTED/BUSY → DONE 或 ERROR → RESET/READY
```

代理不得写入 PLC 拥有的完成位、传感器、安全信号或故障位来制造通过；不得把普通完成
信号解释成故障；不得用固定 `sleep` 替代可观察握手。GUI 维护写入、另一个握手代理和
外部控制器不能同时成为同一节点的写入方。

### 5.2 给 AI/开发者的规范

#### 配置和代码边界

- `config/szlab_handshake.yaml`：连接、默认工作流和时序参数；
- `config/szlab_package.yaml`：设备包就绪场景和运行状态配置；
- `config/szlab_behavior.yaml`：仿真行为、动作延时和可观察状态；
- `szlab_handshake_agent.py`：公开 CLI、OPC UA 会话、动作分派和状态快照；
- `tests/test_szlab_handshake_agent.py`：代理逻辑测试；
- `tests/test_szlab_handshake_opcua_integration.py`：跨进程 OPC UA 接缝测试。

设备包的设备类、资源、动作、工作流和业务协议事实属于 Uni-Lab-SZLab，不应复制到
PLC-Sim。PLC-Sim 只保存硬件无关的仿真行为和协议适配逻辑。

#### 通用动作分派

新增动作时，AI 必须先通过 `list` 或公开配置发现能力，再修改协议配置和动作目录；不能
在主循环中增加“如果当前是某工作流就写这几个节点”的隐式分支。每个动作要说明：

- 动作逻辑 ID 和参数类型；
- 读节点、写节点及其唯一 owner；
- 接受、Busy、完成、错误和复位条件；
- 超时、断线、重复请求和清理语义；
- 是否会影响物理机构，以及仿真与真实 PLC 的差异。

未知动作必须返回明确的“不支持”，不能静默忽略。重复请求不得重入；参数提交后必须等
待 PLC 明确锁存或进入 Busy，之后再修改缓存参数。所有等待都需要超时、最后读值和日志。

#### 最小验证闭环

```powershell
# 代理能力和 CLI 入口
.\.venv\Scripts\python.exe szlab_handshake_agent.py list --config config\szlab_handshake.yaml
.\.venv\Scripts\python.exe szlab_handshake_agent.py --help

# 代理单元/跨进程测试
.\.venv\Scripts\python.exe -m pytest tests\test_szlab_handshake_agent.py -q
.\.venv\Scripts\python.exe -m pytest tests\test_szlab_handshake_opcua_integration.py -q
```

AI 必须用 Server + Agent 的真实进程路径验证，不得以进程内假 OPC UA 对象或直接调用代理
内部函数作为唯一证据。每次变更至少记录配置版本、CSV 摘要、Endpoint、Namespace URI、
动作名称、请求/完成时间、结果和清理状态。

## 6. 常见问题

| 现象 | 检查项 | 处理 |
|---|---|---|
| GUI 打不开工程 | Windows、InoProShop、Node.js、MCP bundle、绝对路径 | 先运行 `structure`，确认公开 MCP 配置；只用 CSV 时跳过工程打开 |
| GVL 没有变量 | GVL 路径、symbol attribute、`--all`、中文注释 | 用 `structure` 找 GVL，使用 `--gvl` 显式指定 |
| Server 启动但代理找不到节点 | Server 是否加载同一 CSV、NodeId/名称/Namespace 是否一致 | 重新导出点表；不要在代理中猜测 NodeId |
| 代理连接后一直等待 | `check` 输出、就绪位、提交边沿、Busy/完成顺序 | 先排除双写入者和残留状态，再检查 PLC 扫描周期 |
| 端口占用 | `4855`、`18765`、`8055` 是否已有旧进程 | 停止旧 Server/代理/GUI，再启动；不要让多个实例共享端口 |
| 启动后动作速度不合适 | `--time-scale`、`--delay-ms`、`--poll-ms` | 仅在仿真中调整；真实 PLC 不应靠倍率改变物理时序 |
| 代理重启后状态异常 | `--state-file`、清理顺序、上一轮提交边沿 | 先停止代理并确认安全初始态，再清理状态文件或重新初始化 |

日志、CSV、状态快照和用户上传文件属于运行数据，不要提交到 Git。出现真实机构、急停、
互锁或物料/库位状态问题时，应由 PLC/设备供应商和 Uni-Lab-SZLab 的公开接口所有者处理，
不能在 PLC-Sim 中伪造现场结论。
