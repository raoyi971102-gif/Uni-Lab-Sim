# SZLab PLC 自动验收包使用说明

版本：0.1（基于 `automation-acceptance` 分支）
适用范围：Windows 10/11 x64 的 SZLab PLC 工程提取、OPC UA 仿真、握手代理和自动化验收。

本文把一个完整操作拆成两条等价路径：

- **使用者路径**：通过 PLC-Sim Web GUI 完成“打开工程 → 导出变量表 → 导入变量表 →
  运行 OPC UA 服务 → 启动握手代理”，再用自动验收包运行门禁；
- **AI/CLI 路径**：通过公开命令行完成同一流程，保留 stdout、进程日志和验收报告作为证据。

这里的“当前实现（Current Implementation）”均以本分支中的 PLC-Sim 和
`plc-acceptance-kit` 为准；没有实现的供应商能力必须标记为 `BLOCKED`、`PARTIAL` 或
`MANUAL`，不能用仿真结果替代真机证据。

## 0. 先分清两个 GUI、两个进程和四个证据等级

| 对象 | 用途 | 是否需要工程编辑器 |
|---|---|---|
| PLC-Sim Web GUI | 打开 InoProShop 工程、提取 GVL 变量表、导入 CSV、启动 OPC UA Server 和 SZLab 握手代理 | 只有“打开工程/提取 GVL/编辑/编译”需要 |
| SZLab PLC 自动验收 GUI | 选择 L1/L2/L3/L4 环境、运行清单、查看 HTML 和 ZIP 证据 | 不需要；连接已有 Endpoint 即可 |

OPC UA Server 和握手代理是两个独立进程。Server 创建点表中的节点；握手代理通过公开
OPC UA/HTTP 接口读取和写入已声明的节点。握手代理不再加载 CSV，也不应通过内部 Python
函数绕过 OPC UA。

证据等级含义如下：

- **L0**：协议、点表、映射和清单的静态一致性；不连接 PLC；
- **L1**：PLC-Sim Server + SZLab 握手代理的独立双进程仿真；
- **L2**：供应商软 PLC 和不可变候选程序包；
- **L3**：有现场位置、监护/见证人的真机台架；
- **L4**：指定现场和物料/批次的 FAT/SAT。

L1 通过不自动升级为 L2/L3/L4。L3/L4 的动作可能影响真实机构，运行前必须完成隔离、
安全确认和人工监护。验收包不部署 PLC 程序、不强写 PLC 所有变量、不旁路急停/互锁。

## 1. 从工程到握手代理

### 1.1 使用者操作（GUI）

#### 1.1.1 准备环境

1. Windows 10/11 x64 上安装 PLC-Sim；使用自动验收安装包时，用户不需要 Python。
2. 只有在需要直接打开和提取 InoProShop 工程时，才需要安装并授权使用：
   InoProShop V1.9.1.6、Node.js 18+，以及项目中的
   `PLC-Sim/vendor/inoproshop-mcp/bundle.min.js`。
3. 准备绝对路径的 `.project` 文件。首次工程提取建议只在维护窗口操作，禁止把
   “下载到在线 PLC”当成导出步骤。
4. 确认本机端口 `4855`、GUI 端口 `18765`、S1 stand-in 端口 `8055` 未被其他实例占用。

#### 1.1.2 打开工程

1. 在 PLC-Sim 目录双击 `start_gui.bat`，或从开始菜单打开 PLC-Sim；浏览器进入
   `http://127.0.0.1:18765/`。
2. 在“工程”区域填写 `.project` 路径，点击“打开工程”。等待 GVL/POU 列表出现后，
   再执行后续操作。
3. “保存”“编译”只用于确认工程可读和程序块可编译。**不要**在验收流程中使用
   `download --strategy online`；在线下载属于非幂等的设备操作，必须由供应商按独立变更流程完成。
4. 若只是使用已有 CSV，可以跳过工程打开，直接进入“OPC UA 仿真”。

#### 1.1.3 导出变量表

1. 切换到“提取变量”页，点击“刷新列表”，选择包含 PLC 通讯变量的 GVL；找不到时，
   先用项目结构确认 GVL 路径，或填写手工 GVL 路径。
2. 点击“预览数据”，检查每行的 `Name`、`EnglishName`、`NodeType`、`DataType`、
   `NodeLanguage` 和 `NodeId`。NodeId 必须来自 PLC/OPC UA 导出，不能按名称猜测。
3. 设置命名空间索引和 NodeId 前缀，使其与供应商点表一致。SZLab 示例常用 `ns=4`，
   但真实工程必须以该工程的 Namespace Array 和导出 NodeId 为准。
4. 需要完整点表时勾选“全部变量/未标记变量”和“展开结构体”；需要保持公开接口最小化时，
   只导出带 symbol attribute 的变量。
5. 使用中文变量名时选择注释/中文名称模式；如果中文注释不稳定，保留英文别名并在
   验收映射中维护逻辑 ID。
6. 点击“提取并保存”，把 CSV 保存到项目外的受控目录。保存后记录文件摘要，现场运行时
   不要在同一文件上边导出边修改。

CSV 最少应有以下列，类型应为 `BOOLEAN`、`INT16`、`INT32`、`FLOAT` 或 `STRING`：

```csv
Name,EnglishName,NodeType,DataType,NodeLanguage,NodeId
工站初始化,Station_Initialize,VARIABLE,BOOLEAN,Chinese,ns=4;s=uniab|工站初始化
```

#### 1.1.4 导入变量表

“导入”在 PLC-Sim 中指把 CSV 交给 OPC UA Server 建节点，不是把 CSV 写回 PLC 工程：

1. 切换到“仿真服务”页，选择 `csv` 配置。
2. 在 CSV 路径框填写刚导出的文件，或通过文件选择器上传。多份 CSV 会合并；同名节点
   以后出现的记录会被跳过，因此应先确认合并顺序和重复项。
3. 设置 Host、Port、Namespace URI、Namespace Index。单机操作建议 Host 使用
   `127.0.0.1`；只有受控网络才使用 `0.0.0.0`。
4. 点击“启动服务”，确认日志中的 Endpoint 与 CSV 摘要正确，再进入下一步。

#### 1.1.5 运行 OPC UA 服务

默认本地 Endpoint 为：

```text
opc.tcp://127.0.0.1:4855/xuse_sim/
```

保持 Server 窗口和 GUI 运行，不要在代理启动后替换 CSV。若需要更换点表，先停止握手
代理，再停止 Server，换表后重新启动双进程并重新运行 L0/L1。

#### 1.1.6 启动握手代理

1. 在“握手代理”区域选择 `SZLab`，填写与 Server 完全一致的 Host、Port 和配置文件
   `config/szlab_handshake.yaml`。
2. 选择“设备包就绪场景”（默认一次启用 Robot、S04 六工位、S05、S06、S07、S08、S09、
   PLC 和 S1 的协议族），需要诊断单一协议时才选择单个工作流。
3. 点击“启动代理”，确认日志显示 OPC UA 已连接、先决条件检查通过，并能在状态页看到
   `state-file` 的最新快照。
4. 代理启动后，再打开 SZLab PLC 自动验收 GUI，选择“内置仿真”运行 L1；不要同时启动
   第二个占用 `4855` 的 Server/代理实例。

关闭时反向执行：先停止握手代理，确认动作已清理并回到安全初始态，再停止 Server；保存
HTML、JSON、JUnit、`timeline.jsonl` 和 ZIP 后才可清理运行目录。

### 1.2 AI/CLI 操作

以下命令在 PLC-Sim 仓库目录执行。开发机可使用仓库虚拟环境；Windows 原生安装包只提供
面向使用者的 GUI，AI 自动化应使用已安装的 Python CLI 或 CI 环境。

```powershell
cd C:\path\to\PLC-Sim
\.venv\Scripts\python.exe -m plc_sim --help
```

#### 1.2.1 打开工程和确认结构

MCP CLI 每次命令都会通过公开 MCP 接缝打开工程；`open --keep-alive` 适合人工检查，
`structure` 适合 AI 读取工程对象树：

```powershell
\.venv\Scripts\python.exe -m ino_mcp.cli structure `
  --project "C:\project\XUSE.project" `
  -o "C:\project\evidence\project-structure.json"
```

如需持续保持会话：

```powershell
\.venv\Scripts\python.exe -m ino_mcp.cli open `
  --project "C:\project\XUSE.project" --keep-alive
```

MCP 找不到依赖时，只通过公开配置修正，不扫描或导入兄弟仓库源码：

```powershell
$env:PLCSIM_MCP_BUNDLE = "C:\path\to\PLC-Sim\vendor\inoproshop-mcp\bundle.min.js"
$env:PLCSIM_INOPROSHOP_EXE = "C:\Program Files\InoProShop\InoProShop.exe"
$env:PLCSIM_NODE = "node"
```

#### 1.2.2 导出变量表

```powershell
$project = "C:\project\XUSE.project"
$csv = "C:\project\evidence\szlab_variables.csv"
$nodePrefix = "uniab|" # 仅示例；必须替换为导出的实际 NodeId 前缀

\.venv\Scripts\python.exe -m ino_mcp.cli extract `
  --project $project `
  --out $csv `
  --gvl "Application/GVL_XUSE" `
  --all `
  --name-mode comment `
  --ns-index 4 `
  --ns-prefix $nodePrefix
```

`--gvl` 可以重复；不确定 GVL 路径时先运行 `structure`。`--all` 导出全部变量，不带它
则只导出带 symbol attribute 的变量。`--name-mode comment` 使用中文注释，必须确认注释
稳定且不与逻辑映射冲突。不要把 `ns-index` 或 `ns-prefix` 当作猜测值提交到验收包。

也可以用 `pipeline` 完成“提取 + 启动 Server”，但它不会启动 SZLab 握手代理：

```powershell
\.venv\Scripts\python.exe -m ino_mcp.cli pipeline `
  --project $project --out $csv --gvl "Application/GVL_XUSE" --all `
  --name-mode comment --ns-index 4 --ns-prefix $nodePrefix `
  --serve --host 127.0.0.1 --port 4855
```

#### 1.2.3 导入变量表并运行 OPC UA Server

CLI 没有单独的“导入 CSV”状态；Server 的 `--csv` 参数就是导入动作。Server 必须使用与
PLC 工程/候选程序相同的点表，握手代理不重复加载该文件。

```powershell
\.venv\Scripts\python.exe -m plc_sim server `
  --host 127.0.0.1 `
  --port 4855 `
  --csv $csv `
  --ns-uri "urn:xuse:sim" `
  --ns-index 4
```

需要合并多张表时重复 `--csv`；多个进程不要复用同一端口。Server 进程保持运行，另开
终端执行后续命令。生产网络中如必须监听所有网卡，应在防火墙和网络隔离已确认后使用
`--host 0.0.0.0`，不要把它作为默认值。

#### 1.2.4 检查并启动握手代理

先列出代理支持的协议族，不连接 OPC UA：

```powershell
\.venv\Scripts\python.exe szlab_handshake_agent.py list `
  --config config\szlab_handshake.yaml
```

再用只读 `check` 检查远端可观察先决条件；它会建立 OPC UA 会话但不启动动作循环：

```powershell
\.venv\Scripts\python.exe szlab_handshake_agent.py check `
  --url "opc.tcp://127.0.0.1:4855/xuse_sim/" `
  --config config\szlab_handshake.yaml `
  --workflow all
```

确认点表和协议族后启动设备包模式：

```powershell
\.venv\Scripts\python.exe szlab_handshake_agent.py serve `
  --url "opc.tcp://127.0.0.1:4855/xuse_sim/" `
  --config config\szlab_handshake.yaml `
  --package-config config\szlab_package.yaml `
  --state-file data\runtime\szlab-package-state.json `
  --s1-host 127.0.0.1 --s1-port 8055 `
  --time-scale 10
```

等价的统一入口是：

```powershell
\.venv\Scripts\python.exe -m plc_sim szlab-handshake `
  --url "opc.tcp://127.0.0.1:4855/xuse_sim/" --time-scale 10
```

`list` 是目录查询，`check` 是只读前置检查，`serve` 才是持续运行的握手代理。对真实
PLC 不应启动这个“仿真代理”作为第二写入方；L2/L3/L4 应由验收运行器直接连接供应商
公开 Endpoint，除非设备供应商明确提供了经过评审的外部适配代理。

#### 1.2.5 运行验收包

先执行不连接 PLC 的 L0：

```powershell
cd C:\path\to\Uni-Lab-Sim
\.venv\Scripts\python.exe -m plc_acceptance.cli validate
```

L1 的 `verify-simulator` 会自行管理 PLC-Sim Server、SZLab 握手代理和 S1 stand-in；
如果已经手动启动相同端口的双进程，应先停止它们：

```powershell
\.venv\Scripts\python.exe -m plc_acceptance.cli verify-simulator
```

连接供应商软 PLC 或真机时，使用 `run`，并提供不可变 PLC 候选包、安全确认以及 L3/L4
要求的现场信息：

```powershell
\.venv\Scripts\python.exe -m plc_acceptance.cli run `
  --environment bench `
  --endpoint "opc.tcp://192.168.1.10:4840/" `
  --namespace-uri "urn:vendor:project:plc" `
  --confirm-safe-test-mode `
  --plc-artifact "C:\evidence\PLC-candidate.zip" `
  --supervisor "供应商张工 / UniLab 李工" `
  --test-location "SZLab 真机台架"
```

L4 还必须增加 `--material-reference "批次 B-20260903"`。`BLOCKED`、`ABORTED` 和未执行的
必跑用例都不能当作通过；`--case` 只用于诊断，不能绕过必跑清单。

## 2. 握手代理建设规范

### 2.1 给使用者看的规范

#### 2.1.1 角色和边界

握手代理（Handshake Agent）是 PLC 的公开协议适配进程：它把“请求、参数、接受/忙、完成、
复位、错误或超时”转换为可观察的 OPC UA/HTTP 交互。它不是 Uni-Lab-OS 的调度器
（Scheduler）、工作流（Workflow）权威，也不拥有物料（Material）、库存（Inventory）或
库位（Site）的第二套状态。

设备包负责设备、资源、动作、工作流和协议事实；PLC-Sim 负责硬件无关仿真；自动验收包负责
逻辑变量、映射、用例、证据和判定。跨仓库只能通过已安装分发包、独立进程、OPC UA、HTTP、
CLI 或其他版本化公开接口连接，禁止源码路径导入、复制实现或调用内部函数。

#### 2.1.2 建设顺序

1. **冻结点表**：从 PLC/OPC UA 导出 `Name`、英文别名、类型、语言、NodeId 和访问属性，
   记录点表摘要；NodeId 不由代理拼接。
2. **定义逻辑变量**：为每个用例分配稳定逻辑 ID，声明数据类型、`owner: host|plc`、
   是否必需和来源；用例只引用逻辑 ID。
3. **定义状态机**：明确就绪、请求/参数锁存、Busy、完成、错误、复位和超时。每个状态
   必须有可观察变量或 HTTP 结果，不能用日志文本代替。
4. **先做一条动作闭环**：在一个设备上完成“清理 → 下发 → 观察接受/Busy → 等待完成 →
   复位”，再扩展到其余设备；每一步有超时和最后读值。
5. **验证独立性**：重复触发、提交后修改参数、重启/断线和非法参数分别验证；缺少公开
   故障或初始化节点时标记 `blocked`，不伪造故障信号。
6. **建立证据链**：记录运行 ID、Endpoint、Namespace URI、映射指纹、协议/清单版本、
   候选 PLC 哈希、每次读写/等待和清理结果；报告中不得写入密码、Token 或完整敏感 payload。

#### 2.1.3 通用动作而不是硬编码工作流

代理应从协议/设备包能力目录生成动作分派表，使用“逻辑动作 ID + 参数模式 + 完成条件”
执行，而不是写死某几条业务流程。新增设备只应新增映射、能力和用例；公共的连接、重试、
超时、复位、证据和安全策略保持一致。

同一请求在执行中再次到达时必须幂等：不得重新入队、覆盖已锁存参数或把旧完成信号当成本轮
完成。未知动作必须显式返回“不支持”，不能静默忽略或猜测 NodeId。动作完成后必须回到
安全可接单态，清理失败则整条用例失败。

推荐的最小生命周期是：

```text
IDLE/READY → ACCEPTED/BUSY → DONE 或 ERROR → RESET/READY
```

参数型握手要求先写完整参数，再提交边沿；提交后先等待 PLC 明确进入 ACCEPTED/BUSY，之后
才能修改中转缓存。固定 `sleep(50)` 不能代替可观察状态；休眠只能作为协议明确要求的最小
防抖，并且仍要等待真实状态。

#### 2.1.4 安全和证据

- `owner: plc` 的完成、传感器、故障、安全和物理结果只能读取，验收包或代理不得写入制造通过；
- 每次等待有超时、逻辑 ID、最后值、耗时和清理状态；人工停止、急停或保护触发标记为 `ABORTED`；
- 本地仿真可以使用 `NoSecurity`，但真实 PLC 应由供应商冻结安全策略和账号；默认绑定回环地址；
- L3/L4 运行前必须确认现场隔离、监护/见证人和位置；L4 还需指定物料/批次；
- 仿真、软 PLC、台架、FAT/SAT 的证据不得混写或互相升级；覆盖矩阵中的 `manual/partial/blocked`
  项始终显示给使用者。

### 2.2 给 AI/CLI 的规范

#### 2.2.1 AI 应读取和修改的边界

自动化验收包只维护下列验收合同，不复制设备包实现：

```text
plc-acceptance-kit/
├── plc_acceptance/bundles/<project>/protocol/
│   ├── plc-interface.yaml       # 逻辑变量、类型、所有权、协议版本
│   ├── test-manifest.yaml       # 必跑用例、环境和安全等级
│   └── requirements-coverage.yaml
├── plc_acceptance/bundles/<project>/mappings/
│   └── <project>.yaml            # 点表路径、Namespace URI、映射版本和摘要
├── plc_acceptance/bundles/<project>/tests/
│   ├── common/                   # 公共握手模式
│   ├── devices/                  # 设备级动作闭环
│   └── project/                  # 串联、异常和重复性
├── plc_acceptance/runner.py      # 唯一运行路径
├── plc_acceptance/validator.py   # L0 静态门禁
└── plc_acceptance/reporting.py   # JSON/JUnit/HTML/timeline/ZIP
```

PLC-Sim 的仿真行为只写在 `PLC-Sim/config/szlab_handshake.yaml`、
`szlab_behavior.yaml`、`szlab_package.yaml` 和公开进程入口中。Uni-Lab-SZLab 的设备类、
动作、资源、工作流、模型和协议事实仍由 `Uni-Lab-SZLab` 持有；不要从验收包导入其源码，
也不要在验收包中新增 Scheduler、Workflow、Material、Inventory 或 Site 权威。

#### 2.2.2 AI 的最小命令闭环

```powershell
# 1) 查看代理目录和参数，不直接改代码猜测能力
\.venv\Scripts\python.exe szlab_handshake_agent.py list --config config\szlab_handshake.yaml
\.venv\Scripts\python.exe szlab_handshake_agent.py --help

# 2) L0：检查合同、点表、所有权、清单和覆盖矩阵
\.venv\Scripts\python.exe -m plc_acceptance.cli validate

# 3) L1：真实跨进程 OPC UA/HTTP 接缝
\.venv\Scripts\python.exe -m pytest PLC-Sim\tests\test_szlab_handshake_agent.py -q
\.venv\Scripts\python.exe -m pytest PLC-Sim\tests\test_szlab_handshake_opcua_integration.py -q
\.venv\Scripts\python.exe -m plc_acceptance.cli verify-simulator

# 4) 读取报告，而不是根据终端的一行 PASSED 推断整包通过
Get-ChildItem plc-acceptance-kit\reports -Recurse
```

命令应保留 stdout/stderr、进程启动参数、退出码和报告目录。AI 不应点击 GUI、调用未发布
的 Python 方法、直接写 OPC UA 底层对象、修改 PLC 拥有的节点或删除失败报告来重跑。

#### 2.2.3 新增一个动作/设备的审查顺序

AI 生成或修改用例前，必须按下面顺序输出变更说明：

1. 来源：设备包/PLC 点表/公开 HTTP 接口的文件或版本；
2. 逻辑 ID、类型、owner、生命周期和可观察完成条件；
3. 请求前置、接受/Busy、完成、错误、复位和超时节点；
4. 对应的 `protocol`、`mapping`、`manifest`、`coverage` 和设备用例文件；
5. 可运行命令及其证据等级；
6. 没有接口时的 `blocked` 原因和供应商关闭条件。

新增用例必须包含 `id`、`name`、`level`、`safety_level`、`environments`、`physical_effect`、
`given`、`when` 和 `cleanup`。步骤只能使用现有 DSL（`write`、`assert`、`assert_greater`、
`wait`、`sleep`、声明服务根下的 `http`）；不得把物理 NodeId、Namespace index、现场地址、
凭据或硬编码设备 ID 写入用例。

#### 2.2.4 AI 的状态和重试规则

- 连接、准入重试、投递重放和执行重试要分别记录，不能统称“重试”；
- 连接断开后先读取并记录最后状态，再决定是否重连；不确定的物理动作不得自动重复下发；
- 重复请求必须携带同一 `run_id`/动作身份并得到幂等结果；旧 `done` 必须先清理，不能当成本轮完成；
- 每次写入后按公开接口回读确认，写入失败、超时、清理失败或状态矛盾都要保留原始证据并终止该用例；
- 必跑用例未执行时总体只能是 `BLOCKED`，不能通过 `--case` 筛选伪造通过。

## 3. 常见问题与证据处理

| 现象 | 先检查 | 正确结论 |
|---|---|---|
| GVL 列表为空 | InoProShop/Node/MCP bundle、工程绝对路径、`structure` 输出 | 修复公开依赖或手工指定 GVL；不能从 PLCId 猜变量 |
| CSV 导入失败 | 表头、UTF-8、数据类型、重复 NodeId、Server 日志 | 修正源点表并重新导出；不要在代理中兼容一个猜测格式 |
| 代理已连接但一直等待 | Server 是否使用同一 CSV、Endpoint/Namespace、节点名称和初始状态 | 记录 `check` 输出；属于配置/点表不一致时为 `BLOCKED` |
| 完成超时 | 接受/Busy 是否先出现、PLC 扫描周期、状态序列、清理结果 | `FAILED` 或 `BLOCKED`，不能增加固定 sleep 伪造完成 |
| 同一个动作重复执行 | 是否有两个代理/GUI 维护写入者、是否残留提交边沿 | 停止第二写入者，清理后重新运行；报告保留冲突证据 |
| L2/L3/L4 无法运行 | 候选包哈希、安全确认、监护人、现场位置、物料批次 | 前置不完整时为 `BLOCKED`，不是“跳过前置继续跑” |
| 安装包被 SmartScreen 拦截 | Release 中的 `SHA256SUMS.txt`、发布来源和签名状态 | 校验哈希后按组织策略放行；当前包没有商业代码签名 |

每次运行至少归档：验收包版本、PLC-Sim 版本、Git 提交、协议/映射/清单摘要、点表摘要、
候选 PLC SHA-256、Endpoint、Namespace URI、运行 ID、用例状态、逐次 `timeline.jsonl`、
HTML/JUnit/JSON 和未关闭覆盖项。运行日志和现场凭据不提交 Git。
